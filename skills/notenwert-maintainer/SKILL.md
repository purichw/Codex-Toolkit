## Core Rules

- Edit source under `src/`; do not edit `notenwert-offline.html` directly.
- `deploy/index.html` and `deploy/sw.js` are generated by `node build.js`.
- `deploy/sw.js` often changes only because the build version changed; do not include it in unrelated commits.
- After source changes, run `node build.js`.
- After meaningful work, update `docs/codex-work-log.md`.
- For every feature or fix, add or update focused coverage in `tests/regression.spec.js` unless the change is docs-only.
- Deploy only from `deploy/` and only when the user asks.

## Compatibility Rules

Do not introduce:

- JavaScript optional chaining `?.`
- JavaScript nullish coalescing `??`
- CSS `inset:0`

Use:

- fixed fallbacks before `clamp()`
- `vh` fallbacks before `dvh` or `svh`
- `@supports` fallbacks for `aspect-ratio`
- `-webkit-backdrop-filter` alongside `backdrop-filter`

## Commit Hygiene

When committing:

1. Inspect `git status --short --branch`.
2. Stage only the intended scope.
3. Leave unrelated dirty files, especially generated build artifacts, unstaged.
4. Use a concise commit message.
5. Push only when the user asks.

## Closeout

Report source files changed, generated deploy artifacts intentionally included or
left unstaged, tests/browser evidence, docs/work-log updates, adjacent skills
used or intentionally not needed, and deploy status.
